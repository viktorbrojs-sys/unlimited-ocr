## [1.0.0] - 2024-08

### Добавлено

- **Локальный сервер OCR** на базе Gradio 6 с FastAPI endpoints
  - Endpoint `/run_ocr` для потокового распознавания изображений
  - Endpoint `/explode_pdf` для конвертации PDF в PNG (постранично)
  - Endpoint `/load_model` для загрузки модели по требованию
  - Endpoint `/model_status` для проверки статуса загруженной модели
  - Endpoint `/` для отдачи фронтенда (index.html)

- **Стриминг результатов** через Server-Sent Events (SSE)
  - Потоковая передача токенов в реальном времени
  - Интервал обновления: 100ms (`stream_every=0.1`)
  - Формат: `{"text": str, "done": bool}`

- **Поддержка моделей** с выбором варианта загрузки
  - `auto` — автоматический выбор (bf16 CUDA → CPU fallback)
  - `bf16` — CUDA bfloat16 (требует ≥16 ГБ VRAM)
  - `cpu` — CPU float32 (очень медленно, но работает без GPU)
  - Автоматический перезапуск сервера для CPU режима с `CUDA_VISIBLE_DEVICES=""`

- **Обработка PDF документов**
  - Конвертация через PyMuPDF (fitz) с DPI=200
  - Постраничная обработка с превью в браузере
  - Временные файлы в `/tmp/pdf_ocr_*`

- **Перехват вывода модели** через патчинг sys.stdout
  - Класс `ThreadTargetedStdout` для фильтрации вывода
  - Игнорирование TPS-сообщений ("tps:", "tokens/s")
  - Отправка только текстового контента в браузер

- **Управление памятью и ресурсами**
  - Блокировка `_infer_lock` для сериализации инференса
  - Блокировка `_model_state_lock` для безопасного доступа к состоянию
  - Очистка временных директорий при выходе (`_cleanup()`)
  - `gc.collect()` и `torch.cuda.empty_cache()` при выгрузке модели

- **Фронтенд из оригинального HuggingFace Space**
  - PDF.js для превью PDF
  - Терминальный вывод с потоковым текстом
  - Выбор режима: LONG (gundam, 640px) / BASE (1024px)
  - Кнопки START/COPY для управления процессом

- **Скрипт установки** `install.sh`
  - Создание виртуального окружения `.venv`
  - Двухшаговая установка зависимостей
  - Обход конфликта версий huggingface-hub

### Изменено

- **Убран декоратор `@spaces.GPU`** — модель работает локально без ограничений по времени
- **Модель загружается по требованию** из веб-интерфейса, а не при старте сервера
- **Двухшаговая установка зависимостей** для обхода конфликта:
  - transformers 4.57.1 требует `huggingface-hub<1.0`
  - gradio 6 требует `huggingface-hub>=1.16`
  - Решение: сначала requirements.txt, потом transformers==4.57.1

### Технические решения

- Перехват `sys.stdout` для стриминга токенов из модели в браузер
- Автоматический `os.execve()` перезапуск для CPU режима
- Временные директории с префиксами `ocr_out_*` и `pdf_ocr_*`
- Параметры инференса по умолчанию:
  - `mode="gundam"` (быстрый, 640px кроп)
  - `prompt="document parsing."`
  - `max_length=8192`
  - `no_repeat_ngram_size=35`
  - `ngram_window=128`

### Известные проблемы

- **Конфликт зависимостей**: pip предупреждает о конфликте huggingface-hub после установки — это ожидаемо, сервер работает корректно
- **Квантование**: Bitsandbytes (8/4-bit) НЕ совместим с архитектурой MoE + R-SWA этой модели
- **VRAM требования**: bf16 режим требует ≥16 ГБ VRAM, на 8 ГБ картах может потребоваться CPU режим
