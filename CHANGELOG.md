## [1.3.1] - 2026-08-21

### Fixed
- После автоматической выгрузки модели из GPU при CUDA OOM во время
  инференса (см. 1.3.0) фронтенд никак не отражал это в UI: переключатель
  DEVICE оставался на GPU (следующий клик LOAD впустую повторял тот же
  обречённый на OOM вариант — именно это видно в реальном логе на карте
  7.49 ГБ: две подряд неудачные попытки bf16 перед тем, как пользователь
  вручную переключился на CPU), а `modelReady` во фронтенде не
  сбрасывался, из-за чего интерфейс мог продолжать выглядеть как "READY"
  для модели, которой на сервере уже нет. `run_ocr()` теперь помечает
  такие ошибки стабильным префиксом `VRAM_OOM:`; фронтенд ловит его в
  обоих местах, где вызывается `/run_ocr` (одиночное изображение и
  постранично для PDF), переключает тумблер DEVICE на CPU (это подсказка,
  не автозагрузка — LOAD всё ещё нажимает пользователь), сбрасывает
  `modelReady` и обновляет статус. Для PDF дополнительно останавливает
  обработку остальных страниц — они всё равно упадут с той же причиной,
  раз модель уже выгружена.

## [1.3.0] - 2026-08-21

### Changed — BREAKING
- Режим **`auto`** для `/load_model` убран целиком (был единственным
  значением по умолчанию). Теперь `variant` принимает только `"bf16"`
  или `"cpu"` — без скрытой цепочки фолбэков. UI теперь отдельно
  выбирает **устройство** (GPU/CPU) и, для GPU, **точность** (`bf16`,
  дропдаун оставлен на будущее — вдруг появятся другие варианты).
  Причина: авто-цепочка на загрузке не спасала от реального сценария
  OOM (см. ниже) и маскировала, какой вариант в итоге загрузился.
- `/run_ocr` получил новый параметр `ngram_guard: bool = True`.

### Fixed
- **CUDA OOM во время самого инференса** (не при загрузке — модель уже
  была на GPU, не хватило VRAM на конкретное изображение/активации)
  раньше не обрабатывался вообще: модель оставалась висеть на GPU без
  освобождения VRAM, никакого уведомления пользователю, а поле "auto"
  всё равно не помогало, потому что его фолбэк-логика была только на
  этапе `from_pretrained()`. Теперь `_infer_thread` в `run_ocr()` ловит
  CUDA OOM отдельно, явно выгружает модель (`model = None`,
  `torch.cuda.empty_cache()`, `gc.collect()`) и поднимает понятную
  ошибку с просьбой переключиться на CPU — без скрытого автовыбора за
  пользователя.
- После рестарта сервера в CPU-режим (`os.execve()`) фронтенд раньше
  просто зависал — SSE-соединение рвётся, обычный пользователь не
  понимал, что делать (кроме как вручную обновить вкладку). Теперь
  фронтенд детектирует стадию рестарта, показывает счётчик времени,
  поллит `/` до первого успешного ответа и сам делает
  `location.reload()`, сохраняя выбор устройства (`?device=cpu` в URL)
  через перезагрузку.
- Тумблер **NGRAM** в шапке был чисто декоративным — JS нигде не читал
  его состояние, а `no_repeat_ngram_size=35` был захардкожен в `app.py`
  независимо от него. Теперь тумблер реально передаётся в `/run_ocr`
  (`ngram_guard`) и управляет, применяется ли `no_repeat_ngram_size`.
- Финальный "чистый" текст (из `.txt`/`.md`) больше не дублируется
  визуально, если он совпадает с уже показанным вживую во время
  инференса — раньше он всегда переигрывался заново, из-за чего вместе
  с батчингом `stream_every=0.1` посимвольный вывод из 1.2.2 всё равно
  выглядел как мгновенная вспышка текста, а не печатающая машинка.
  Теперь: если текст совпадает — просто показывается как есть; если
  отличается — идёт настоящая посимвольная анимация, но ограниченная по
  времени (~200 шагов, максимум ~2.4 сек, независимо от длины текста).

### Changed
- DPI конвертации PDF-страниц в изображения (`pdf_to_images`) поднят с
  200 до 300 по умолчанию — выше эффективная плотность пикселей на
  символ, должно улучшить распознавание мелкого текста.

### Added
- Пояснение разницы между режимами **LONG** и **BASE** — во всплывающих
  подсказках (`title`) на соответствующих кнопках в UI и развёрнуто в
  `README.md`.

## [1.2.3] - 2026-08-21

### Removed
- Вариант модели **AWQ 4-bit** (`sahilchachra/Unlimited-OCR-AWQ`) убран
  из списка вариантов (`awq` больше не принимается, `auto` больше не
  пробует его первым) и из зависимостей (`autoawq`, `compressed-tensors`
  убраны из `requirements.txt`). Причина: `compressed-tensors`
  разжимает веса в fp16 непосредственно перед инференсом, так что
  реального выигрыша по VRAM или скорости в рантайме от AWQ нет (только
  меньший объём при скачивании) — на карте с 8 ГБ VRAM он всё равно
  упирается в OOM, то есть даже теоретическая цель "влезть в 8 ГБ" не
  достигается. При этом остаётся риск потери точности OCR из-за
  сторонней, неофициальной реквантизации модели, для которой точность —
  это весь смысл продукта. Чистый минус без единого практического плюса.
  `auto` теперь пробует **bf16 → CPU**.

## [1.2.2] - 2026-08-21

### Fixed
- `run_ocr()` больше не мог зависать с сообщением «Another OCR run or
  model load is in progress» после успешно завершённого запроса: лок
  `_infer_lock` теперь освобождается сразу после того, как поток
  инференса завершён и результат прочитан из файла, а не в самом конце
  тела генератора. Раньше освобождение зависело от того, что
  SSE-стриминг-обёртка вызовет `next()` ещё один, «лишний» раз уже
  после payload'а с `"done": true` — если обёртка трактует
  `done: true` как сигнал «сообщений больше не будет» и на этом
  прекращает опрашивать генератор, тело функции так и остаётся
  подвешенным на последнем `yield`, `finally` с `_infer_lock.release()`
  никогда не выполняется, и лок держится вечно.

### Changed
- Финальный «чистый» текст (прочитанный из `.txt`/`.md`,
  `_collect_output()`) теперь стримится клиенту посимвольно, как в
  референсном HF Space от Baidu, а не блоками по 5 слов.

## [1.2.1] - 2026-08-20

### Fixed
- `app.py` содержал продублированные блоки кода в нескольких функциях
  (артефакт неудачного слияния веток), из-за чего файл не проходил даже
  `python -m py_compile` — сервер не запускался вообще. Все дубли убраны.
- `run_ocr()` теперь удерживает `_infer_lock` на весь запрос, а не только
  внутри рабочего потока — устраняет гонку, при которой параллельный вызов
  `load_model()` мог выгрузить/подменить модель прямо во время инференса.
- `install.sh` больше не ставит `bitsandbytes`/`accelerate` — они не
  используются в коде и, по архитектуре модели (MoE + R-SWA), несовместимы
  с этим способом квантования.
- `start.sh` больше не удаляет `~/.cache/torch/` при каждом запуске и
  корректно устанавливает закреплённую версию `transformers==4.57.1`
  (раньше не устанавливалась, что приводило к рассинхрону версий).

### Removed
- Мёртвый код: неиспользуемый импорт `AutoAWQForCausalLM` с
  несуществующим kwarg'ом `low_zero` в `_variant_kwargs()`.
- Нерабочий цикл повторных попыток по занятому порту в `start.sh`
  (переменная `PORT` не пробрасывалась в процесс — `app.py` и так сам
  инкрементирует порт при занятости).
- Служебные файлы, случайно попавшие в репозиторий: внутренние заметки
  AI-агента (`memory/`) и разовая личная инструкция по миграции
  (`UPDATE_INSTRUCTIONS.md`).

### Changed
- Документация реорганизована: единый `README.md` для быстрого старта,
  `CONTRIBUTING.md` для процесса разработки, `docs/ARCHITECTURE.md` для
  технических деталей, `ROADMAP.md` для планов — вместо дублирующих друг
  друга `PROJECT_DOCS.md`/`DEVELOPMENT_PLAN.md`.
- Добавлен `.github/workflows/syntax-check.yml` — `py_compile`/`shell -n`
  на каждый push и PR, чтобы синтаксическая ошибка не могла снова попасть
  в `main` незамеченной.
- Расширен `.gitignore` (временные папки OCR, кеш Gradio, `*.env`).

## [1.2.0-AWQ] - 2026-08-18

### Added
- Поддержка AWQ 4-bit квантованной модели
  (`sahilchachra/Unlimited-OCR-AWQ`, ~3-4 ГБ VRAM вместо ~14 ГБ) —
  делает проект пригодным для GPU с 8 ГБ VRAM.
- Автоматическая цепочка фолбэка при загрузке: AWQ → bf16 → CPU,
  с уведомлением пользователя при переключении из-за нехватки VRAM.
- Файл `VERSION` и отображение версии в интерфейсе.
- `start.sh` — скрипт для обновления из GitHub, очистки кеша Gradio
  и запуска одной командой.

## [1.1.0] - 2026-08-17

### Fixed
- Гонки состояний и некорректная работа блокировок при параллельной
  загрузке модели и инференсе.
- Загрузка модели в CPU-режиме при видимом CUDA приводила к ошибке
  «tensors on different devices» — теперь сервер сам перезапускается
  с `CUDA_VISIBLE_DEVICES=""` для консистентного CPU-режима.
- `NameError` из-за порядка объявления `app = Server()` относительно
  `@app.api()`-эндпоинтов.

### Changed
- Модель грузится по требованию из веб-интерфейса (выбор варианта:
  auto/bf16/cpu), а не сразу при старте сервера — сервер поднимается
  мгновенно.
- Автоинкремент порта при занятости `7860`.

## [1.0.0] - 2026-08-16

### Added
- Локальный сервер на базе Gradio 6 `Server` + FastAPI-эндпоинты:
  `/run_ocr` (потоковое OCR через SSE), `/explode_pdf` (PDF → PNG
  постранично), `/load_model`, `/model_status`, `/` (отдаёт `index.html`).
- Стриминг результатов распознавания через перехват `sys.stdout` модели.
- Обработка PDF через PyMuPDF (`fitz`), DPI=200.
- Фронтенд — прямой порт `index.html` из оригинального HF Space, без
  изменений интерфейса.
- `install.sh` — двухшаговая установка зависимостей (обход конфликта
  версий `huggingface-hub` между gradio 6 и `transformers==4.57.1`).
