# Roadmap

Статус реален на момент последнего обновления этого файла (см. `git log
-- ROADMAP.md`). Перед тем как браться за пункт — проверьте, не решён ли
он уже, и загляните в [`CHANGELOG.md`](CHANGELOG.md).

## Готово

- [x] Локальный порт HF Space (Gradio 6 Server + FastAPI, без `@spaces.GPU`)
- [x] Ленивая загрузка модели по требованию из UI
- [x] Поддержка AWQ 4-bit (`sahilchachra/Unlimited-OCR-AWQ`) — работает
      на GPU с 8 ГБ VRAM
- [x] Автоматический фолбэк при загрузке: AWQ → bf16 → CPU, с
      уведомлением пользователя при переключении из-за OOM
- [x] Автоперезапуск сервера для консистентного CPU-режима
      (`CUDA_VISIBLE_DEVICES=""`)
- [x] Автоинкремент порта при занятости
- [x] Постраничная обработка PDF с превью
- [x] Синхронизация блокировок между загрузкой модели и инференсом
      (см. `docs/ARCHITECTURE.md`)
- [x] CI-проверка синтаксиса (`.github/workflows/syntax-check.yml`)

## Приоритет 1 — стабильность и производительность

- [ ] Обработка ошибок для PDF с повреждёнными/нечитаемыми страницами
      (сейчас `pdf_to_images` упадёт на всём файле, если одна страница битая)
- [ ] Явный `gc.collect()`/`torch.cuda.empty_cache()` между страницами
      многостраничного PDF — снизить пиковое потребление памяти
- [ ] Прогресс-бар для многостраничных PDF (сейчас пользователь видит
      только текущую обрабатываемую страницу)
- [ ] Кэширование результатов OCR для повторных запросов к тому же файлу

## Приоритет 2 — функциональность

- [ ] Пакетная обработка нескольких файлов за раз
- [ ] Экспорт результатов в DOCX/TXT/MD/JSON (сейчас только copy-to-clipboard)
- [ ] Настройка параметров инференса через UI (`max_length`,
      `no_repeat_ngram_size`, `ngram_window`, `base_size`/`image_size`) —
      сейчас захардкожены в `run_ocr()`
- [ ] История OCR-сессий
- [ ] Drag-and-drop нескольких файлов одновременно

## Приоритет 3 — интеграции

- [ ] REST API для использования не только через встроенный UI
      (текущие эндпоинты завязаны на Gradio `Server`/SSE-контракт фронтенда)
- [ ] `Dockerfile` + `docker-compose.yml` для контейнеризации
- [ ] Интеграция с облачными хранилищами (S3, Google Drive)
- [ ] Webhook-уведомления после завершения OCR

## Приоритет 4 — мониторинг

- [ ] Логирование запросов/ответов в файл
- [ ] Метрики производительности (время обработки, размер файла, длина текста)
- [ ] Health-check эндпоинт для мониторинга
- [ ] Экспорт метрик в формате Prometheus

## Приоритет 5 — документация и тесты

- [ ] Unit-тесты для ключевых функций (`_variant_kwargs`, `_collect_output`,
      `_target_labels` — не требуют GPU/весов, легко тестируются изолированно)
- [ ] Integration-тесты полного пайплайна OCR (потребуют мок модели или
      маленький тестовый чекпоинт)
- [ ] OpenAPI/Swagger-документация эндпоинтов

## Отложено / под вопросом

- [ ] **NVFP4** (для архитектуры Blackwell/RTX 50xx) — требует CUDA 12.8+,
      PyTorch 2.6+, риск нестабильности библиотек. Модель:
      `sahilchachra/Unlimited-OCR-NVFP4` (если существует на момент работы —
      проверьте актуальность).
- [ ] **Apple Silicon / MLX** — `mlx-community/Unlimited-OCR-{4,6,8}bit`,
      требует MLX-фреймворк, отдельная ветка загрузки модели.
- [ ] **GGUF / llama.cpp** — универсальный CPU/GPU формат через
      `llama-cpp-python`, не должен ломать текущую архитектуру, делать
      опциональным.
- [ ] Поддержка альтернативных OCR-моделей (EasyOCR, Tesseract, PaddleOCR)
      для сравнения качества.
- [ ] Fine-tuning на специфичных доменах, распознавание рукописного текста.
- [ ] Десктопное GUI-приложение (Electron/Tauri) поверх текущего сервера.
