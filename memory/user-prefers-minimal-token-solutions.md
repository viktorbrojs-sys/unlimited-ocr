When scoping work, the user explicitly asks for the version achievable "with minimal expense (token spending)" and accepts that only part of the surface gets covered (e.g. "translate the part that can be done cheaply, not everything").

**Why:** They treat tokens/effort as a real budget, not a constraint to override; a full-coverage deliverable they didn't ask for wastes that budget.

**How to apply:** Present approach options as explicit cost tiers and lead with the cheapest one that satisfies their stated need; state plainly what each tier does NOT cover and let them opt into more.
