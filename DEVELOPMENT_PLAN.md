# План доработок Unlimited OCR

## Тестовое окружение
- **GPU**: NVIDIA GeForce RTX 5060 (8 ГБ VRAM)
- **Driver**: 580.173.02
- **CUDA**: 13.0
- **ОС**: Linux Mint

---

## План А: Быстрый старт (приоритет №1)

### Цель
Запустить проект в максимально нативном режиме с минимальными изменениями, проверить качество распознавания.

### Задачи
1. **Интеграция AWQ (4-bit) версии модели**
   - Использовать квантованную версию: `sahilchachra/Unlimited-OCR-AWQ` или аналогичную
   - Модель займет ~3-4 ГБ вместо 14+ ГБ
   - Работает на всех современных GPU NVIDIA (включая RTX 5060/5090)
   - Требует библиотеку `autoawq` или `transformers` с поддержкой AWQ

2. **Автоматическое переключение при OOM**
   - При ошибке CUDA Out Of Memory автоматически загружать модель на CPU
   - Выводить уведомление пользователю о переходе на CPU
   - Логировать причину переключения

3. **Интерактивный выбор режима в UI**
   - Добавить выпадающий список: ["Auto", "CUDA (AWQ 4-bit)", "CPU float32", "CPU int8"]
   - Режим "Auto": пытается AWQ на GPU → при ошибке CPU
   - Серым цветом отмечать недоступные режимы (если железо не поддерживает)
   - По умолчанию: "Auto"

4. **Улучшение обработки ошибок**
   - Четкие сообщения об ошибках для пользователя
   - Рекомендации по решению проблем (например, "Недостаточно VRAM, выберите CPU режим")

### Ожидаемый результат
- Приложение запускается на RTX 5060 с AWQ моделью
- При нехватке памяти автоматически переходит на CPU
- Пользователь видит статус и может выбрать режим вручную

## План Б: Альтернативные варианты (приоритет №2)

### Цель
Попробовать более новые форматы сжатия для максимальной производительности.

### Задачи
1. **Поддержка NVFP4 (для архитектуры Blackwell)**
   - Формат специально для серии RTX 50xx
   - Максимальная скорость и минимальный размер
   - Требования: CUDA 12.8+, PyTorch 2.6+, свежие драйверы
   - **Риск**: нестабильность библиотек, сложность установки

2. **Тестирование производительности**
   - Сравнить скорость AWQ vs NVFP4
   - Измерить использование памяти
   - Оценить качество распознавания

### Ожидаемый результат
- Опциональная поддержка NVFP4 для пользователей с RTX 50xx
- Документация по установке дополнительных зависимостей

## Перспективные доработки (приоритет №3)

### Цель
Расширение поддержки платформ и улучшение проекта.

### Задачи
1. **Поддержка Apple Silicon (MLX)**
   - Интеграция моделей в формате MLX (4/6/8-bit)
   - Запуск на MacBook с чипами M1/M2/M3
   - Использование фреймворка MLX от Apple

2. **Поддержка GGUF / llama.cpp**
   - Универсальный формат для CPU и GPU
   - Возможность запуска на системах без мощного GPU
   - Интеграция через `llama-cpp-python`
   - **Важно**: не ломать текущую архитектуру, сделать опциональным

3. **Пакетная обработка файлов**
   - Обработка нескольких PDF/изображений за раз
   - Прогресс-бар для длительных операций
   - Сохранение результатов в файл

4. **Настройки качества**
   - Выбор разрешения для изображений
   - Настройка параметров генерации текста
   - Языковые настройки

5. **API режим**
   - REST API для интеграции с другими системами
   - Поддержка WebSocket для стриминга результатов

## Технические заметки

### Модели для тестирования
- **Оригинал**: `baidu/Unlimited-OCR` (~14 ГБ, требует много VRAM)
- **AWQ 4-bit**: `sahilchachra/Unlimited-OCR-AWQ` (~3-4 ГБ)
- **NVFP4**: `sahilchachra/Unlimited-OCR-NVFP4` (~2-3 ГБ, только RTX 50xx)
- **GGUF**: `sahilchachra/Unlimited-OCR-GGUF` (для CPU/llama.cpp)
- **MLX**: `mlx-community/Unlimited-OCR-{4,6,8}bit` (для Apple Silicon)

### Зависимости
```bash
# Для AWQ
pip install autoawq

# Для NVFP4 (требует свежие версии)
pip install torch --upgrade
pip install transformers --upgrade

# Для GGUF (перспектива)
pip install llama-cpp-python

# Для MLX (перспектива, macOS)
pip install mlx-lm
```
