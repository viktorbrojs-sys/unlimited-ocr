# ИНСТРУКЦИЯ ПО ОБНОВЛЕНИЮ unlimited-ocr до версии 1.2.0-AWQ

## Проблема
Изменения были сделаны в локальной ветке `/workspace`, которая не связана с вашим удалённым репозиторием на GitHub. Поэтому при `git pull` вы получаете старую версию без поддержки AWQ.

## Решение (2 варианта)

### Вариант А: Ручное копирование файлов (быстро)

1. **Скопируйте файлы из `/workspace` в ваш проект:**

```bash
cd ~/unlimited-ocr

# Копируем основные файлы
cp /workspace/app.py ./app.py
cp /workspace/index.html ./index.html
cp /workspace/requirements.txt ./requirements.txt
cp /workspace/start.sh ./start.sh
cp /workspace/VERSION ./VERSION

# Делаем start.sh исполняемым
chmod +x start.sh

# Устанавливаем зависимости
.venv/bin/pip install -q "autoawq>=0.2.6"

# Запускаем
.venv/bin/python app.py
```

2. **Откройте браузер на http://127.0.0.1:7860**

3. **В интерфейсе вы увидите:**
   - Выпадающий список MODEL с опциями:
     - `auto (AWQ → bf16 → CPU)` - автоматически пробует AWQ сначала
     - `AWQ 4-bit · ~3-4 GB VRAM (recommended)` - ручная загрузка AWQ
     - `bf16 · ~7 GB VRAM (full precision)` - полная точность
     - `CPU · slow but works` - режим CPU
   - Кнопку LOAD для загрузки модели
   - Версию приложения будет видно после обновления index.html

### Вариант Б: Полная переклонирование (надёжно)

```bash
cd ~
rm -rf unlimited-ocr-temp
git clone https://github.com/viktorbrojs-sys/unlimited-ocr unlimited-ocr-temp
cd unlimited-ocr-temp

# Копируем обновлённые файлы из /workspace
cp /workspace/app.py ./app.py
cp /workspace/index.html ./index.html
cp /workspace/requirements.txt ./requirements.txt
cp /workspace/start.sh ./start.sh
cp /workspace/VERSION ./VERSION

# Коммитим и пушим
git add .
git commit -m "feat: Add AWQ 4-bit support and version tracking (v1.2.0-AWQ)"
git push origin main

# Возвращаемся к основному репозиторию
cd ~/unlimited-ocr
git pull origin main
```

## Что изменилось в версии 1.2.0-AWQ

### Новые возможности:
1. **Поддержка AWQ 4-bit модели** (`sahilchachra/Unlimited-OCR-AWQ`)
   - Размер модели: ~3-4 ГБ вместо 14+ ГБ
   - Работает на RTX 5060 с 8 ГБ VRAM
   
2. **Автоматический fallback при CUDA OOM**
   - При нехватке видеопамяти автоматически переключается на CPU
   - Показывает уведомление пользователю

3. **Интерактивный выбор режима в UI**
   - 4 режима работы: AWQ, bf16, CPU, auto
   - Автоматическое определение недоступных режимов

4. **Версионирование приложения**
   - Файл VERSION содержит номер версии
   - Версия отображается в интерфейсе и при запуске

5. **Скрипт запуска start.sh**
   - Автоматическое обновление из GitHub
   - Очистка кэша Gradio и PyTorch
   - Установка зависимостей
   - Обработка конфликтов портов

## Проверка работы

После запуска выполните тестирование:

1. **Тест AWQ режима:**
   - Выберите "AWQ 4-bit" в выпадающем списке
   - Нажмите LOAD
   - Загрузите изображение или PDF
   - Проверьте наличие распознанного текста

2. **Тест CPU режима:**
   - Выберите "CPU" в выпадающем списке
   - Нажмите LOAD (сервер автоматически перезапустится)
   - Загрузите изображение
   - Проверьте результат

3. **Тест автоматического fallback:**
   - Выберите "auto"
   - Если AWQ не поместится в VRAM, должно произойти авто-переключение на CPU
   - Появится уведомление о переключении

## Требования к оборудованию

| Режим | Мин. VRAM | Рекомендуемое железо | Скорость |
|-------|-----------|----------------------|----------|
| AWQ 4-bit | 4 ГБ | NVIDIA RTX 3060+ | Быстро |
| bf16 | 8 ГБ | NVIDIA RTX 3080+ | Очень быстро |
| CPU | 16 ГБ RAM | Любой CPU | Медленно |

**Ваше оборудование:** NVIDIA RTX 5060 (8 ГБ) - идеально подходит для AWQ режима!

## Контакты

- `autoawq>=0.2.6` установлен
- Браузерный кэш очищен (Ctrl+F5)
- Порт 7860 не занят другим процессом
